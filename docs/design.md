# 設計

konomi の目的は、持ち主の好みを AI が分析できるようにすることである。
記録をどのサービスから取ってくるかは手段で、プロバイダーとして差し替えられるようにする。
分析と MCP のツールは特定のサービスを知らない。

## 記録の形

記録は「何に」と「どうしたか」に分ける。

対象（subject）は、動画・曲・アルバム・アーティスト・チャンネル・人・再生リストなど、好みの向かう先である。
プロバイダーの中の ID と種類、題名、URL、長さ、公開日を持つ。
対象どうしはクレジットでつながる。動画の投稿者や曲のアーティストも対象の 1 つで、
動画からその投稿者へクレジットを張る。フォローした人と、見た動画の投稿者が同じ対象になるので、
サービスの中で「よく見る人」と「フォローしている人」を突き合わせられる。
タグとジャンルは対象に付ける。

反応（signal）は、持ち主が対象にしたことである。
種類は、見た・聴いた（consumed）、高評価した（endorsed）、マイリストや再生リストに入れた（collected）、
フォロー・登録した（followed）の 4 つに絞る。collected は入れた先の名前を文脈に持つ。

consumed は出来事なので、同じ対象でも時刻が違えば別の反応にする。
ほかの 3 つは状態なので、対象と文脈ごとに 1 件だけ持ち、最初に見つけた時刻を残す。

## プロバイダー

プロバイダーは、ログイン情報とカーソルを受け取って、新しい観測とカーソルを返す関数である。
観測は「この対象に、いつ、この種類の反応をした」という 1 件で、対象の中身とクレジットとタグを含む。
保存、重複の除去、分析はプロバイダーの外で行う。

ログイン情報の取り方は、プロバイダーが方式の一覧として宣言し、画面は方式ごとの入力欄をこの宣言から作る。
カーソルはプロバイダーが決める文字列で、中身は外から見ない。初回は空で、遡る量もプロバイダーが決める。

ログイン情報が切れたとき、方式が取り直しに対応していれば、プロバイダーの renew で取り直して保存し直す。
取り直せなければ「入れ直しが要る」状態にする。
取り込みの途中でログイン情報が更新されたとき（回された Cookie など）も、観測と一緒に返して保存する。

プロバイダーを足すときは、`apps/web/src/features/ingest/api/providers/` に 1 つ置き、一覧に加える。

## MCP のツール

`search_signals` は、語・反応の種類・対象の種類・プロバイダー・期間で反応を引く。
`taste_profile` は、よく反応したクレジット先・タグ・対象の種類と反応の種類ごとの件数をまとめる。
`list_connections` は、プロバイダーごとの取り込みの状態を返す。入れ直しが要るとき、AI が持ち主に伝えられる。
